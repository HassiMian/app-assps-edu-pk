# APEX Connect mobile/shared school NAT browsing (V3.6, 2026-10-04)

The previous `generalLimiter` capped the entire server at 120 requests/minute by `req.ip`, including `/auth/me`, settings and ordinary dashboard navigation. Four authenticated synthetic browser sessions behind the same test IP reproduced unrelated accounts seeing 429. A school with hundreds of students behind a single connection is especially exposed.

- `generalSessionSubject` reads only an HS256 JWT from the HTTP-only `authToken` cookie and verifies it with the configured `JWT_SECRET` before constructing `school:<tenant>:user:<id>`. Unsigned `userId`, `tenantId`, role cookies and untrusted XFF never establish identity. Invalid/expired tokens remain on the public/IP quota.
- Verified active sessions: 180 requests/minute **per authenticated user**. Public/invalid-session requests: 240 requests/minute **per verified incoming network IP**. These two stores are separate. Default library handling retains IPv6-safe public IP keys. Trusted real visitor IP forwarding remains controlled by Nginx/one-hop Express trust-proxy rules.
- Login and password-reset endpoints are excluded from generic browsing quotas but retain dedicated controls: 60 requests/15min per network+hashed login identifier; backend 5 incorrect-password/account+network block; recovery 20/15min per IP. Additional login network-flood ceiling 480/min per verified IP prevents login identifier rotation from bypassing abuse controls while accommodating school NAT login rushes. All limits remain enabled.
- Health checks are not consumed by regular browsing quotas. No fake auth cookie may bypass the public quota; user tokens must be signed with production secret.
- Isolated test `tests/mobile-browse-limiter.test.js`: 180 requests for signed user A allowed, next blocked, different signed user B on same IP remains available, unsigned `userId` never bypasses public 240/IP cap. Test sends only requests to an intentionally unknown route, never school data mutations. Set `TEST_SERVER_PORT=5016` for a separately launched backend.
- Tests `tests/login-fair-rate-limit.test.js`, `tests/portal-role-isolation.test.js`, `tests/verified-proxy-cookie.test.js` pass against production after update. The previous login test's public `/auth/me` rate header expectation changed from 120 to 240, preserving independent login ID quotas.

This is shared backend infrastructure servicing Connect and the school SaaS, **not** a change to attendance/paper editor or tenant permissions. Separate school SaaS working tree remains untouched; source is committed in the isolated backend release checkout.
