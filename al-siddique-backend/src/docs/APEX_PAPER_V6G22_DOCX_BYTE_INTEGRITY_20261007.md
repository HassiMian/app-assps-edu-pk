# APEX Paper Studio V6-G22 — Canonical DOCX Byte Integrity

V6-G22 adds transport-verifiable SHA-256 binding to the revision-bound canonical DOCX generated by G21. It does not change source authority, curriculum approval, publisher approval, persistence, or canonical-write state.

## Contract

For every successful canonical DOCX download, the backend computes SHA-256 over the exact emitted DOCX bytes and returns the hex digest in `X-ASSPS-DOCX-SHA256`.

The digest is calculated after the revision/snapshot/family eligibility gates have passed and from the exact `Buffer` sent to the client. The existing `X-ASSPS-Paper-Revision` and `X-ASSPS-Snapshot-Hash` bindings remain unchanged.

## Verification

HTTP acceptance recomputes SHA-256 from the downloaded response body and requires exact equality with `X-ASSPS-DOCX-SHA256`.

## Safety invariants

- source mutation: false
- persistence: false
- academic approval changed: false
- publisher approval changed: false
- canonical write changed: false
- approval claim: false
- legacy DOM exporter used: false

G22 is byte-integrity evidence only.
