## Cloudflare immutable-asset cache incident and safe versioning

Immediately after live origin chunk repair, the origin HTTP SHA256 matched the fixed artifact `c649e289...`, but public Cloudflare `cf-cache-status: HIT` with long `max-age=2592000, immutable` returned **old** SHA256 `597b9cae...` and thus users could still see the same crash. A cold client hard refresh cannot be accepted as sufficient CDN invalidation. The recovery uses an HTML [import map](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script/type/importmap) in the non-cached application shell, mapping only the dynamic Employees module path to a new content-addressed asset `/assets/EmployeesModule-c649e289.js`. The original index JS hash, shared React chunks, all unrelated modules and routes remain untouched. Standalone real headless Chromium verified that this import-map remapping loads the newly versioned lazy module rather than the immutable cached old URL: **PASS**. Guarded script `employees-access-cache-bust-20261013.py` enforces exact runtime root, HTML base checksum, existing patched chunk hash, and source release commit, and retains the original shell for rollback. Genuine Principal session visual acceptance still required before declaring the Credentials screen completely accepted.
