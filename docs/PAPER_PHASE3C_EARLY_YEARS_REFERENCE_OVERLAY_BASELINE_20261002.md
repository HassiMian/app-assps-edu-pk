## Important limitations / acceptance gates
1. No live teacher/school browser approved-state export has been created by these synthetic tests. The principal must select the ACTUAL approved edited worksheet on their authenticated browser, save the DATA baseline, record its original Preview screenshot and original native A4 PDF while keeping source, template and fonts unchanged. Compare all three before allowing a new renderer or migration.
2. SHA-256 in the JSON snapshot is an integrity checksum, NOT a server signature or authorization. A party able to rewrite the baseline and recompute hashes could forge it. Verified server revisions and approval must use authenticated, school-scoped, append-only audit controls later.
3. The older EarlyYearsWorksheetEditor has existing React hook-lint warnings/errors related to its preexisting setState-in-effect/manual memoization. The new Phase 3C modules are linted independently. Do not refactor unrelated rendering lifecycle merely to satisfy lint before capturing baseline visual screenshots.
4. Legacy template map is still unscoped, and session-uploaded art is still volatile. Both are explicitly recorded, not silently repaired by this read-only feature. Durable tenant-specific template/art persistence requires independently versioned schema and migration, backup+restore verification and renderer parity.
5. No production, backend schema, examination marks, PaperGenerator source corpus, saved paper library or original V2 reference file is modified in this phase.
6. Existing Phase 3A 101 corpus hash guard, Phase 3B native snapshot and CAS tests, Class 8 Urdu compact workspace, all 9 Early Years render/print/geometry and canonical 43 paper screen-vs-print regressions are release gates before any controlled production cutover.
