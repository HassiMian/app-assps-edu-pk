## Actual identified regression and fix (fail before, pass after)

1. `DailyDiaryWorkspace.jsx` constructs an independent iframe for Print / PDF. Its printed `.dd-sub-cell` CSS contained `justify-content: center !important` and `text-align: center !important`, incorrectly overriding the subject's inline teacher selection/right alignment for Urdu subjects. This contradicted canonical editor Urdu/RTL print fidelity.
2. Extended `dailyDiaryWorkspaceBrowserAcceptance.test.js` to compare **computed style** of actual `.dd-sub-cell.urdu` on-screen against the isolated print iframe. **Fail-before executed:** print `center` vs screen `right` (`Print iframe changed Urdu subject alignment`), Node TAP 0/1. Fixed only the forced print-centering styles so existing per-subject inline `justifyContent`/`textAlign` win; no other layout styles or school metadata removed. **Pass-after executed:** browser accepted Urdu alignment, 10-card A4 page composition, school/student text parity, and actual headless Chromium A4 PDF generation.
3. Teachers can adjust subject font size and bold. The browser regression explicitly clicked the per-subject size increase and Bold toggle, asserted an actual change to the on-screen cell, and compared its inline `fontSize` and `fontWeight` against the print iframe. **PASS:** no subject-size/bold control regression; paragraph/diary content preserved.
4. The old print method called `iframe.contentWindow.print()` after a blind 350 ms, regardless of actual fonts or school logo/image load. The new method waits for iframe `document.fonts.ready` and image load/error completions, with **bounded 2,400 ms watchdog** so offline external fonts cannot hang printing. A request token suppresses an older asynchronous print firing on a newer iframe snapshot. Browser fallback to `window.print()` remains. No font binaries/third-party content are redistributed.
5. Additional independent scoped browser suite `ops/paper-studio/run_diary_release_browser_20261016.cjs`: **4/4 PASS**: print layout/controller, Save → Reopen and foreign-tenant denial, and late-save selection race, all synthetic server/Chromium, no hardware printing. The extended single browser test produced an **actual ~101,905-byte A4 PDF** from the new iframe (ephemeral in-memory, not persisted). These outcomes are test evidence, **not** accepted physical school hardcopy.
