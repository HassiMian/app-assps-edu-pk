## Reproduced defect on actual reviewed source

The saved Daily Diary API supports a historical row shape `{subject,homework}`; canonical teacher-facing `DailyDiaryWorkspace.jsx` expects `{subject,diary}` when it renders or prints. Its `loadDiaryRecordIntoEditor` previously passed returned rows through unchanged. Newly extended true end-to-end test created and persisted a synthetic School1 teacher diary using legacy English and Urdu `homework` fields in a real disposable PostgreSQL16 cluster, authenticated through actual school selector + JWT, loaded the saved document through the **real Saved Diaries Library / Load / Edit UI**, then inspected preview. Before the source fix the test **failed**: both English and Urdu homework were displayed as `—` despite the actual saved database content. This is genuine reproducible schema-compatibility loss in preview, **not** a confirmed incidence in live school diaries. Test did not mutate live DB.

## Narrow source correction and empty-field safety

The editor's single `loadDiaryRecordIntoEditor` read path now copies each row and derives `diary` from the legacy `homework` **only if the `diary` value is not already a string**. Explicitly empty `diary:''` retains its meaning, even if stale `homework` is present. Other row fields including `subjectFontSize`, `subjectBold`, Urdu alignment, row IDs and source `homework` are preserved. No database DDL, data rewrite, permission changes, font files or backend changes; the same mapping covers explicit Reopen, Saved Diary library Load and Duplicate flows.
