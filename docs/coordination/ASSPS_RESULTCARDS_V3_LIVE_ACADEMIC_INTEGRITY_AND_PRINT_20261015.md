# ASSPS Result Cards V3 — Academic Integrity & Print Stability Release

Date: 15 October 2026 (~23:34 PKT). **Active static frontend** `/var/www/assps-resultcards-premium-v3-20261015`, public `https://app.assps.edu.pk/exams/results`.

## Why the release was needed
Read-only grade/roster audit on exact First Term exam 9, School1: **302 students / 1,762 saved subject results**, but **232/302** had fewer saved subjects than the official class-section roster, with **283 missing subject-result cells**. In the legacy 10-template V2, missing subject rows were invisible to the percentage reducer (rather than treated as pending). Integer inclusive grade bands have fractional gaps; backend Core already includes a pure `selectGradeBand` helper using floor for integer band endpoints. A Preview All print button bypassed the normal print-readiness preflight. All 81 exam-subject setup rows remain school approval status `pending`, and approval was NOT fabricated.

## Delivered V3 frontend-only, non-destructive
1. Exam term catalog fetched from existing, authorized school-scoped `GET /api/exams?include_subjects=1` (same backend compatible with school login). For each student, official class+section+subject offerings are reconciled against saved exact subject marks. Missing offerings append visible `PENDING` presentation-only rows (`marks_obtained=null`), NEVER stored zeros or new exam_result rows. Unexpected or unverified subjects also flag academic `DRAFT`.
2. Every premium result-card printout carries a visible `DRAFT RESULT — Pending/unverified, not approved` or `AWAITING ACADEMIC APPROVAL` flag. Whole-class panel displays provisional card count. User gets explicit opt-in before printing a draft. No data mutation or simulated teacher/principal academic signing.
3. Grade calculation now uses the same exact integer-threshold interpretation as current Core backend: whole-number grade bands use `Math.floor` of the *unrounded percentage* for lookup, preserving displayed percentage and all actual saved score rows. Ambiguous or incomplete ranges fail closed with `—` rather than inventing a grade. Tests include 39.999, 59.99, 69.999, 89.999 and 100.
4. Preview All's `Print / Save PDF` button now calls `window.__asspsValidatedResultPrint`, shared with automatic printing, verifying ready school logos, fonts and A4 table/footer overflow. Preview mode never triggers a printer automatically. Browser integration test forces actual card overrun via measured `scrollHeight` and proves printing is blocked.
5. Original 10 diverse professional templates preserved, including new Scholars Archive. Whole-Class / Section / Optional Student / All Classes are unchanged, with one card per A4 page; First Term source isolation remains.
6. Future releases can fail closed using compiled active-asset guard `ops/release/verify-resultcards-v3-active-20261015.cjs` and 8 negative/adversarial tests checking subject roster, pending labels, both print preflights, ten themes, and route identity.
