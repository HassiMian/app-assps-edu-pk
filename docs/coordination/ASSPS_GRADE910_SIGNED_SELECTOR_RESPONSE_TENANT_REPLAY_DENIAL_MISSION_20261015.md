## Specific additional academic-publication safeguard actually implemented

The restricted Grade IX–X server-side paper picker previously relied on school/grade/subject-scoped SQL, teacher assignment SQL, school-signed core gate and cryptographic signature/revision eligibility, but its JSON response filtered only by `eligible(row)`. An otherwise validly signed **different school** publication returned by a buggy DB adapter could therefore pass the cryptographic eligibility predicate without verifying the requesting authenticated actor's school identity one more time. This is defense in depth: **NOT** a demonstrated production tenant exposure or a replacement for RLS.

Added `al-siddique-backend/src/services/grade910PickerResponseScope.js` and wired it inside `al-siddique-backend/src/routes/grade910VerifiedPickerRoutes.js`, **before rendering any approved selectable record**. It rejects every response row where the DB result school ID, grade or case-folded subject differs from the authenticated request. On the `resolve-revision` endpoint it also matches the exact original question ID, integer revision and immutable 64-character SHA. It retains existing signature validation, actual tenant-scoped SQL, teacher assignment, signed school gate and revoked/approval checks. No new school authority or signed publication grant is created.

This is particularly relevant to the canonical teacher/principal **Save → Reopen → Print** workflow: a signed row for a different original academic revision must never be returned as though it were the requested exact revision. School identity comes exclusively from the server session; no user-provided school ID is trusted.
