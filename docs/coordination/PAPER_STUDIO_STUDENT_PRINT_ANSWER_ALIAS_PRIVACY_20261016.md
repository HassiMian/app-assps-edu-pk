## Genuine source weakness reproduced fail-before

The server-side Assessment Studio service `al-siddique-backend/src/services/assessmentPrintJobs.js` builds `STUDENT_SAFE` print projections by recursively removing sensitive answer-key metadata. However its forbidden key registry did not include several *actually used* canonical Question Bank and teaching source keys: `answerText`, `correctOptionId`, `answerExplanation`, `correctAnswerIndex` or the hyphen/underscore spellings. The original normalization also retained underscores. The canonical frontend source uses `correctOptionId` extensively and the Question Bank sync imports `answerText`. As a result those metadata values could appear in a student-facing projection if the signed print snapshot included them. This is a source-level exposure risk demonstrated with a synthetic snapshot, **not evidence that actual student papers were exposed or printed**.

Added new adversarial domain test with an actual mixed-case Question Bank-like release snapshot. **Fail-before:** existing eight domain tests passed but the new test failed (`Student-visible answer alias leaked: PRIVATE_ANSWER_TEXT`); no network/live school requests. Staff answers and source data were not mutated during test.

## Narrow fix and positive verification

Only the server projection's denylist/normalization were changed: sensitive answer metadata names are canonicalized as lower-case alphanumeric keys, treating `correctOptionId`, `correct_option_id` and `correct-option-id` equivalently. Exact sensitive known key aliases are rejected recursively from personalized student output: answer text, answer explanation, correct option ID/index and answers among existing protected fields. Avoid generic stripping of all keys containing `answer`, because layout fields such as `answerLines` must remain for lined response spaces. The authorized staff `STAFF_ANSWER_KEY` path retains the original detailed answer information; the immutable signed release JSON is not mutated. No tenant/RLS, marks, print geometry, school student record or printing settings change.

Observed post-fix: **9/9** assessment print domain tests PASS, **2/2** separate authenticated/tenant/print projection static boundary tests PASS, total **11/11**; none failed or skipped. Private print suite uses a synthetic mock class with two Seven students, one Eight student and deliberate `PRIVATE-*` phone/address fields. Original browser harness had incomplete API interception, causing a synthetic auth redirect to `/login`; this was NOT attributed to live teacher login. Added a safe loopback-only no-network default API stub registered *before* each explicit fixture response. Actual isolated Chromium personalized duplex printing then PASS (1/1): paper finalized, two selected student name/roll booklets, 2 duplex blank pages, print job `CREATED → QUEUED → PRINTING` durable API binding, no extra class, minimal roster payload with no contact details, and actual iframe HTML contains no private phone/address, answer-key or active script/iframe/embed elements. Chromium no real printer/spooler usage. Private log: `/root/paper_studio_private_qa_20261016/student-answermetadata-personalized-browser.log`.
