# Phase 3X — Authenticated teacher-only signed Curriculum projection

Date: 3 October 2026. Parent Phase3W: `7034361500547f63552c96a4aa5f311ce4f0395d`.

## Missing integration now prepared
Phase3V previously verified a signed original-record publication, but returned no signed
chapter/topic display registry. Phase3W could pin an existing projection but no backend-owned
conversion from signed records to a Phase3P-compatible teacher Question Bank read model existed.
Phase3V now returns `topicRegistry` as an exact clone of the independently signed payload.
New `teacherCurriculumProjectionPhase3X.js` converts only verified signed source contents
into the preexisting Phase3P read-only projection schema, already pinned with Phase3W lineage.
No source answers/text/translations, chapter titles or topic labels are generated by AI.

## Future signed taxonomy payload extension (required; never silently synthesized)
Each `topicRegistry` entry must contain `chapterId`, `chapterNumber`, bilingual chapter
titles (`enChapterTitle`, `urChapterTitle`), canonical `topicId`, bilingual topic titles
(`enTopicTitle`, `urTopicTitle`), independently sourced per-language topic IDs
(`enSourceTopicId`, `urSourceTopicId`) and verified page ranges
(`enPageStart`, `enPageEnd`, `urPageStart`, `urPageEnd`).
The entire enriched registry MUST be included BEFORE Phase3V Ed25519 signing. Phase3X
rejects absent/duplicate/misaligned taxonomy, chapter numbering, source topic IDs or
questions whose official source pages fall outside the signed ranges.
The existing Phase3V signed envelope permits these enriched fields, but the
Curriculum agent has NOT yet published a real approved enriched registry.

## Server-only authorization and privacy
`createPhase3XTeacherProjection` requires trusted backend-injected `authenticate`,
`resolveSubjectGrant` and the independently verified Phase3V `approvedProvider`.
Only active school teacher/principal/admin identities with positive school/user IDs
and independently resolved tenant identity are eligible. Student, parent, platform
and service accounts are explicitly denied before retrieving any academic records.
The subject grant must be ACTIVE/AUTHORIZED and bound to the same server actor, role,
school, tenant, textbook authority, grade, subject, edition and syllabus version.
School/tenant identifiers are passed from the trusted actor alone, not request headers.
Never send this full teacher projection to unauthenticated/student/browser-public routes:
it necessarily contains source answers, reviewer evidence and full original academic records.

## Source preservation and downstream integration
The output contains the preexisting Phase3P schema, bilingual registered chapter/topic
menus, MCQ options with exact verified A–D IDs, short/long original stems and answers,
and deep-cloned complete original academicRecord objects. A correct MCQ ID also must
agree with original English AND Urdu answer texts, otherwise the projection is rejected.
Revision/publication ID/signed records digest are included as a read-only Phase3W pin.
The result is ALREADY pinned: downstream Phase3Q can consume `result.projection` directly.
Do not attach Phase3W a second time. Phase3P/3Q/3R preserve the original records and
student-only Phase3R projection strips answer keys. Print/save/production flags remain FALSE.
Phase3S still re-resolves the current signed provider at persistence time and is the sole
server approval boundary. Changing a browser projection cannot authorize persistence.

## Regression and activation boundary
10 new synthetic Ed25519-based tests cover authenticated projection, end-to-end
Phase3V → Phase3X → Phase3Q → Phase3P → Phase3R, original Urdu/English and MCQ accuracy,
teacher-only role/grant restrictions, nonexistent signed taxonomy, page/edition drift,
forged academic data, and stale publication revision. Real academic approval is NOT claimed.

or production activation, and refuses construction when NODE_ENV is production.
Production enablement still requires authoritative Curriculum Issue #1 publication,
independent school/teacher enrolment resolver, issuer key custody, an approved API privacy
review, actual Phase3S/3T connector tests, full corpus acceptance, Urdu layout/print parity
and independent rollback/backup authorization.
