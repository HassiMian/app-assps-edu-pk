## Connected printer requirement: what is genuinely supported
- Nine premium result layouts do **not** hardcode a Ricoh/HP/Epson/Brother driver, IP address, network share, printer name, or print queue. A4 portrait and one-page-per-student semantics are expressed as standards-based print CSS.
- Teacher presses **Print · Choose Printer**. After strict marks/grade/identity/tenant-logo/batch overflow preflight, the app invokes native browser `window.print()`. Chrome/Edge/Firefox delegate USB/Wi-Fi/network/shared printer selection and physical print job ownership to the **current computer's OS printer/driver/spooler**. Teacher selects whichever compatible connected/installed printer they want; the app does not lock selection. A4/portrait/100% actual-size guidance provided.
- **Save as PDF** is separate but uses the same protected A4 cards through the browser print-to-PDF dialog. No hidden direct backend print service or remote driver emulation. If OS-browser has no print API, printing fails visibly; if logo or content is invalid, printing fails closed before asking the OS to print.
- **Hardware limitation, not a claimed pass:** It is impossible for an ordinary isolated SaaS web page to enumerate/manage arbitrary client OS print queues or guarantee hardware compatibility without installing an explicitly authorized local printing connector. Connected Windows desktop reported STANDBY/POWER SAVING (more than 8 hours); `Get-Printer` fell back into Linux shell with error. VPS has no CUPS/printer spooler. Thus installed physical printer list, spool state, real paper output, drivers and media-specific A4/color validation CANNOT honestly be certified in this environment. No real school printer command executed.
