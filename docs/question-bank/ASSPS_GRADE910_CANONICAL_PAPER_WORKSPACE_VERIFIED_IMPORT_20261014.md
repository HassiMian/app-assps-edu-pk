# ASSPS Grade IX–X — Canonical Paper Workspace approved-only revision integration (14 October 2026)

## Fixed final missing product integration
The previously separated Grade IX–X selector only exported a manifest and could not insert a question into the teacher's real Paper Workspace. This implementation **integrates directly** into `PTSPaperGenerator.jsx` / its actual `QuestionPanel` paper state:
- In new Grade IX/X (not previously completed protected official) papers, `Grade910WorkspaceApprovedInsert.jsx` displays *school server-approved* questions with subject and exact teacher section. It retrieves the `/api/grade910-verified-picker/approved-only` read-only school-scoped list. Before one-click insertion, it re-resolves its **exact** original question ID + revision + question SHA on the server.
- A source-approved MCQ/short/long is mapped into actual `paper.mcq/short/long` arrays with immutable revision, source/answer/grant fingerprint metadata, original chapter/medium, per-question verified marks, and a snapshot of every rendered critical question field/option.
- The existing **real Paper Workspace Save, Finalize, Print and personalized batch print** commands now revalidate each embedded verified question against the **genuine server publication ledger** (JWT/RLS/active teacher class-section-subject assignment) and its immutable source/answer revision and release grant. Changed text, chapter, medium, answer option, or section marks, revoked publication, wrong subject/grade, stale question revision, no signed server or offline source => operation BLOCKED. A paper may contain independently authored manual questions, but manual questions never gain an academically verified badge/claim.
- Existing manually authored drafts, non-IX/X classes, previously completed protected official papers, historical 43 finished papers, whole-school diary, original 2,581 source revisions and student's Exam9 marks are untouched.

## Additional cryptographic publisher hardening
Previous publication ledger required good SHA fields and three boolean approval statuses, but a database field itself is not a human-signature proof. The server contract now **also cryptographically verifies** Ed25519 `publication_signature_base64` over a domain-separated canonical JSON signed payload binding:
`school_id`, original question ID/revision, both exact question & answer SHA, grade/subject/medium, source catalog/PDF, verified independent faculty review, school book adoption, principal approval, publication grant, three accepted release gates and publication time.

Publisher Ed25519 PUBLIC key and SHA-256 fingerprint are provided **out of band** via `ASSPS_GRADE910_PUBLISHER_PUBLIC_KEY_PEM` and `ASSPS_GRADE910_PUBLISHER_TRUST_FINGERPRINT_SHA256`. Missing key, wrong fingerprint, forged signed school/teacher digest, malformed signature or altered answer SHA always fail closed; no signing private key or fabricated faculty certificate is in source. Academic institutional verifier remains separate and must issue approved school-root/roster-bound release receipts before any real publication row is inserted. New additive selector migration `031_grade910_verified_paper_selector.js` requires the signature column and signed restricted RLS.

## Additional root-cause resolution — actual canonical Save/Reload/Print, not a detached manifest
An isolated review found that user-authored assessments persist **only `official_section`** as canonical paper nodes. An earlier first-pass importer inserted verified MCQs/shorts/longs into the legacy arrays but not these canonical sections, which would have lost the verified question in actual server persistence. This was corrected **before release**:
- `createGrade910ApprovedSection` now creates an actual rendered `official_section` for every imported signed question, carrying the exact signed question text, MCQ choices, reviewed marks, answer key, immutable source/grant ref and rendered-content snapshot.
- `createManualAssessmentDocument` embeds the rendered sections into real canonical `PaperDocumentV2` nodes and separately preserves signer-bound `academicVerifiedSelections` metadata in the **server-persisted** canonical document. On reopening, `rehydrateGrade910VerifiedPaper` reconstructs the verified question arrays/sections from signed metadata if the local copy is missing; tampered metadata is fail-closed, never silently represented as approved.
- Source-only backend `grade910PaperWorkspaceReleaseGuard` requires genuine JWT teacher/principal school context, exact teacher grade/subject/section assignment, out-of-band pinned Ed25519 publication root, unchanged canonical text/marks/MCQ answer and approved, nonrevoked original question+answer revision. **Assessment Studio revision Save, Finalize, new print job and reprint** all call this server-side release gate for canonical documents that contain signed Grade IX/X references. Legacy nonverified manual paper behavior remains unchanged.
- `assessmentPrintJobs.buildStudentSafeProjection` now strips the entire private canonical `academicVerifiedSelections` metadata and `correct` option flags from student print projections, retaining staff answer-key projection under its separate staff RBAC. This avoids leaking reviewed answer keys and teacher certificate metadata in a printed student package.
