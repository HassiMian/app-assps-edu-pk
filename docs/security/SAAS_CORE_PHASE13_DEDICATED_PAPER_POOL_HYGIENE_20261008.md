## Genuine new trust-boundary fix
- Before: `connectRestrictedPaper()` called bare `raw.release()` when independent DB login authorization, HMAC preparation or signed-RLS role verification failed. On an existing signed Paper transaction, the lease ignored `ROLLBACK` cleanup errors and returned the physical connection to the reusable pool. Its explicit `COMMIT/ROLLBACK` wrapper also set `open=false` on failed SQL, then release could return an uncertain backend as clean.
- The isolated fix extracts a **test-only-exposed but normal-production-used** `createRestrictedPaperLease(raw)`. It tracks transaction completion error separately. Successful `COMMIT` or `ROLLBACK` and successful implicit rollback return clean sessions normally, preserving pooling. If either explicit transaction completion fails, or automatic release rollback fails, lease passes the transaction error (`PAPER_DB_ROLLBACK_FAILED` on implicit rollback) to `pg-pool release(error)` **so pg-pool evicts the backend**. A setup, login-role, actor, signature or policy validation exception is also passed into `raw.release(err)`, not silently reused after catch. Repeated release is idempotent. No broader DB grants, Paper visibility or protected official data changed.
- This is a narrowly scoped failure-handling hardening. No evidence that a real production tenant leak happened; signed policy is not enabled on production. No migration, DB SQL or production role/credential operation was executed.
